## 摘要（约 300 字，可按需删改）

本文设计并实现了一个面向个人写作者的多用户博客网站「微光博客」。系统采用 Servlet + JSP + JavaBean
的三层结构，数据持久化使用 JDBC 访问 SQLite 单文件数据库，会话状态通过 HttpSession 维护，并综合运用过滤器、
监听器完成统一编码、登录鉴权、权限控制与在线人数统计。系统实现了用户注册登录、个人资料与头像管理、
文章发表编辑删除、分类与标签管理、关键词搜索、分页浏览、评论、点赞、文件上传下载以及管理员后台等
完整业务闭环。设计中的主要难点在于：多条件动态 SQL 与分页的总数一致性、多对多标签关系的查询效率
（避免 N+1 查询）、文件上传的安全校验（重命名与后缀白名单）以及并发场景下的计数准确性。
测试表明系统功能完整、响应正常，页面在桌面与移动端均可正常使用。

关键词：Servlet；JSP；JDBC；会话管理；过滤器

## 1 引言

博客是最典型的「读多写少 + 强交互」的内容型 Web 应用：游客浏览、作者写作、读者评论，
三条链路分别对应不同的权限与状态管理需求，很适合用来检验课程所学的服务端技术。
现有博客平台功能完备但难以二次开发，因此本项目的目标是自己动手实现一个结构清晰、可讲解、
可扩展的小型博客系统，把 Servlet 生命周期、会话管理、过滤器链、监听器事件、文件上传下载、
JDBC 事务与分页这些知识点落到实际代码里，而不是停留在示例级别。

预期成果：一个可在 Tomcat 9 + SQLite 上直接运行的 war 工程，具备注册登录、发文评论、
分类标签搜索分页、上传下载、权限过滤、站长后台与全站统计，并附数据库文件、表结构脚本与说明文档。

## 2 需求分析

### 2.1 业务分析

系统有三条主业务流程：

1. **写作流程**：注册/登录 → 进入发文页 → 填写标题/正文/分类/标签 → 选择发布或存草稿 → 跳转详情页；
2. **阅读流程**：首页列表（分页）→ 分类/标签/关键词筛选 → 详情页（浏览量 +1）→ 点赞或评论；
3. **管理流程**：管理员登录 → 后台概览（用户/文章/评论/在线人数/PV）→ 管理文章与评论。

### 2.2 用户分析

| 角色 | 权限 | 典型操作 |
|---|---|---|
| 游客 | 只读 | 浏览、搜索、按分类标签筛选、查看评论 |
| 注册用户 | 读写自己的内容 | 发文/改文/删文、评论、点赞、改资料、传头像 |
| 管理员 | 全部 | 以上全部 + 后台概览 + 编辑/删除任意文章或评论 |

### 2.3 功能分析

功能模块：用户模块（注册、登录、退出、资料、头像）、文章模块（发表、编辑、删除、详情、草稿）、
检索模块（分类、标签、关键词、分页）、互动模块（评论、点赞）、文件模块（上传、导出下载）、
管理模块（后台概览、内容管理）、公共模块（编码过滤、登录拦截、权限拦截、在线统计、错误页）。

## 3 系统设计

### 3.1 功能模块图（画成框图）

```
微光博客
├── 用户模块：注册 / 登录 / 退出 / 资料 / 头像上传
├── 文章模块：发表 / 编辑 / 删除 / 详情 / 草稿
├── 检索模块：分类 / 标签 / 关键词 / 分页
├── 互动模块：评论 / 删除评论 / 点赞
├── 文件模块：封面上传 / 头像上传 / 文章导出 / 文件下载
├── 管理模块：后台概览 / 文章管理 / 用户列表 / 最新评论
└── 公共模块：编码 / 自动登录 / 未读徽标 / 登录 / CSRF / 权限 6 个 Filter、3 个 Listener、统一错误页
```

### 3.2 权限设计

- 认证：登录成功后 `User` 对象放入 `HttpSession`（key = `loginUser`），
  登录时调用 `request.changeSessionId()` 更换会话 ID，防会话固定攻击；
- 鉴权：`AuthFilter` 拦截需登录的地址（发文章、评论、点赞、改资料、传头像），
  未登录时 AJAX 请求返回 401 JSON，普通请求 302 到登录页并带上 `next` 参数；
  `AdminFilter` 拦截 `/admin`，非管理员返回 403；
- 数据级校验：普通用户的 UPDATE/DELETE SQL 带 `user_id = ?`；管理员使用显式 DAO 分支；草稿仅作者或管理员可预览、导出。

### 3.3 系统结构设计

```
浏览器（JSP + EL + JSTL + 少量原生 JS/fetch）
   │  HTTP
   ▼
Filter 链：Encoding → AutoLogin → NoticeBadge → Auth → Csrf → Admin
   ▼
Servlet（控制层：取参数、校验、调 DAO、转发视图）
   ▼
DAO（数据访问层：PreparedStatement + try-with-resources）
   ▼
SQLite（data/blog.db，8 张表，单文件存储、外键约束 + WAL）
```

视图统一放在 `WEB-INF/views` 下，只能由 Servlet 转发，杜绝绕过控制层直接访问页面。

### 3.4 界面设计

统一视觉规范：暖白底 + 墨绿主色（#2f6e5f），卡片式列表，圆角 14px，正文 15px/1.75 行高，
支持 `prefers-color-scheme` 深色模式与 900px / 640px 两档响应式断点。
页面清单：首页（列表+侧栏）、详情页、发文页、登录、注册、个人中心、后台、错误页。

### 3.6 数据库设计（8 张表）

| 表 | 说明 | 关键字段 |
|---|---|---|
| `users` | 用户 | id, username(唯一), password, salt, nickname, email, avatar, bio, role, created_at |
| `categories` | 分类 | id, name(唯一), sort_order |
| `posts` | 文章 | id, user_id(FK), category_id(FK), title, summary, content, cover, view_count, like_count, status, created_at, updated_at |
| `tags` | 标签 | id, name(唯一) |
| `post_tags` | 文章-标签（多对多） | post_id + tag_id 联合主键，两个外键均级联删除 |
| `comments` | 评论（支持二级回复） | id, post_id(FK 级联), user_id(FK), **parent_id(FK 自关联，NULL=一级评论)**, content, created_at |
| `post_likes` | 点赞 | post_id + user_id 联合主键（天然防重复点赞） |
| `notifications` | 站内通知 | id, user_id(接收者), actor_id(触发者), type(COMMENT/REPLY), post_id, comment_id, is_read, created_at |

索引：`posts(user_id)`、`posts(category_id)`、`posts(created_at)`、`comments(post_id, created_at)`、
`comments(parent_id)`、`notifications(user_id, is_read, created_at)`、`post_tags(tag_id)`。
SQLite 使用 UTF-8 文本存储并在每个连接启用外键约束；通知、文章标签等关系按业务需要配置级联删除。

## 4 具体实现

### 4.1 技术选型

Java 8 语法（JDK 21 编译）· Servlet 4.0 / JSP 2.3 / JSTL 1.2 · SQLite 3 + sqlite-jdbc 3.45.3.0 ·
Tomcat 9 · Maven war 打包 · 前端原生 HTML/CSS/JS（无框架、无 CDN，可离线演示）·
JUnit 5（单元测试）· java.util.logging（日志，Tomcat 自带无需依赖）。

### 4.2 文件结构

见 `README.md` 第二节（含命名规则）。

### 4.3 代码实现（建议在报告中贴的片段）

1. **登录与会话**：`LoginServlet.doPost()`（Session 存 User + `changeSessionId()` + 清空敏感字段）；
2. **统一编码**：`EncodingFilter.doFilter()`；
3. **登录拦截**：`AuthFilter.doFilter()`（区分 AJAX 与普通请求）；
4. **动态 SQL 与分页**：`PostDao.search()` 与 `buildWhere()`（COUNT 与 LIMIT 共用条件）；
5. **多对多标签的一次性填充**：`TagDao.mapByPostIds()`；
6. **点赞一致性**：`PostDao.toggleLike()`（SQLite 下串行化切换，关联记录与计数在单连接事务内同步）；
7. **上传安全**：`UploadUtil.saveImage()`（UUID 重命名 + 后缀白名单 + 大小限制），
   `WebUtil.safeImageUrl()` 只允许 `/upload/cover/` 或 HTTP(S)，JSP 属性使用 `c:out` 转义；
8. **下载中文文件名、路径越界与草稿导出权限防护**：`DownloadServlet`；
9. **在线人数**：`OnlineUserListener`（`AtomicInteger` 原子计数 + `CopyOnWriteArrayList`）；
10. **Cookie 显式编程**：`RememberMeUtil.buildToken()/verify()/writeCookie()/findCookie()` +
    `AutoLoginFilter.doFilter()`（HMAC 签名 + 密码盐做密钥 + 滑动续期）；
11. **过滤器顺序**：`web.xml` 中 6 个 `<filter-mapping>`（顺序即执行顺序：编码 → 自动登录 → 未读徽标 → 登录 → CSRF → 管理员）；
12. **二级回复 + 通知**：`NoticeService.notifyComment()`（通知谁、去重规则）+ `CommentDao.findById()`；
13. **日志与异常**：`Logs.init()` + `BaseServlet.fail()`（先记日志再抛出）。
14. **CSRF 防护**：`CsrfUtil.token()` 生成 32 字节随机令牌存 Session，`head.jspf` 输出
    `<meta name="csrf-token">`，14 处 POST 表单注入 `_csrf`、AJAX 走 `X-CSRF-Token` 头，
    `CsrfFilter` 对写请求用 `MessageDigest.isEqual` 定长比较，失败返回 403（AJAX 回 JSON）；
    不用 Cookie 双提交，避免「没带字段也能通过」；退出登录由 GET 改为 POST。
15. **事务**：`PostDao.insert/update`（文章 + 标签关联）与 `CommentService.addComment()`
    （评论 + 通知）都是单连接显式事务，异常回滚、`finally` 复位自动提交。

调试过程中解决的主要问题（写进报告很加分）：

1. **POST 中文乱码**：`setCharacterEncoding` 必须在第一次取参数前调用，改为在 Filter 里统一设置；
2. **JSP 中文乱码**：被 `include` 的 `.jspf` 会按默认编码（ISO-8859-1）单独解码，
   静态中文变成「å¾®å…‰」，必须在每个 JSP/片段里显式声明 `pageEncoding="UTF-8"`；
3. **`${page.empty}` 报 EL 解析错误**：`empty` 是 EL 的运算符关键字，改用 `${empty page.list}`；
4. **发文 500**：表单漏写 `enctype="multipart/form-data"` 时 `getPart()` 抛
   `InvalidContentTypeException`，改为先判断 `Content-Type` 再取部件；
5. **列表总数与列表条数不一致**：COUNT 与 LIMIT 用了两份条件，抽取 `buildWhere()` 统一生成；
6. **标签列表 N+1 查询**：改为一次 `IN (...)` 查完再回填；
7. **改了昵称页面不更新**：Session 里的 User 是同一个对象，需同步 set 后再回显；
8. **中文下载文件名乱码**：使用 `filename*=UTF-8''` 编码（RFC 5987）。

## 5 总结

本项目完成了从需求分析、数据库设计到编码测试的完整流程，把课程中的七项技术全部用在了真实业务里：
Servlet 承担控制流程，JSP + EL + JSTL 负责展示，JDBC 完成持久化，Session 管理登录状态，
Filter 解决编码与鉴权这类横切问题，Listener 完成启动自检与统计，上传下载补齐文件能力。

主要收获：一是理解了「会话」的本质是服务器端的一张 Map，浏览器只持有 key，围绕它才能讲清登录、
拦截、超时与安全；二是认识到框架解决的问题（参数封装、连接池、模板引擎）都是可以自己手写的，
手写一遍之后再学 Spring MVC 会轻松很多；三是体会到边界条件比主流程更考验功力——分页越界、
重复提交、非法路径、并发计数，这些问题在演示时不会出现，上线后一定会出现。

不足与改进方向：正文目前为纯文本，可引入 Markdown 渲染并做白名单过滤；无连接池，高并发下应换
DataSource；上传文件存在部署目录，应改为独立存储；可继续扩展草稿箱定时发布、文章收藏、
用户私信、图片压缩与缩略图。
